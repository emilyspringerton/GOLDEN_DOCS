# GOLDEN_DOCS — Claude Code Context

## What this is

A full, real, git-tracked snapshot of every EINHORN_INDUSTRIAL golden doc (per
`EMILY/context/golden-docs-index.md`) plus core EMILY context files. See this repo's own
`README.md` for the real layout and purpose.

## CONSTRUCT File Generation (Principle 21, monorepo-wide)

`.github/workflows/construct.yml` auto-generates `GOLDEN_DOCS_CONSTRUCT.txt` +
`GOLDEN_DOCS_MANIFEST.txt` (a deterministic, git-ls-files-based plaintext snapshot of every
tracked file, verified byte-for-byte reproducible on every run) on every push/PR to `main`,
uploaded as a CI artifact. No manual work needed, and no manual edit — see the root `CLAUDE.md`'s
own "Principle 21: CONSTRUCT Files" section for the shared pattern this follows
(`scripts/generate_construct.sh`, modeled directly on `IDUNA/scripts/generate_iduna_construct.sh`).
This repo's own `MANIFEST.md` (per-golden-doc hashes, generated by the sync script, not this
workflow) is a separate, unrelated file.

**Auto-releases**: on every real push to `main` (never on a PR), the same workflow tags
(`v<date>-<run_number>` — the run number, not just the date, since this repo can resync more than
once a day and each sync should get its own release) and publishes a real GitHub Release carrying
the construct + manifest + a zip of both. Verified live, 2026-09-21 (first CI run:
`success`, run `35573504305`).

## Regenerating / syncing this repo (manual, until CI automation lands)

This repo has no source of its own — every file here is a plain copy of a file from the main
monorepo (`/home/fatbaby`). Whenever a golden doc changes there (added, removed, or meaningfully
edited), or `EMILY/context/golden-docs-index.md`/`full-system-context.md`/the sprawl memo/
`golden-repos.json` changes, resync this repo:

```bash
cd /home/fatbaby
python3 - <<'PYEOF'
import os, shutil

paths = []
with open("EMILY/context/golden-docs-index.md") as f:
    for line in f:
        line = line.rstrip("\n")
        if not line.startswith("|"):
            continue
        parts = [p.strip() for p in line.split("|")]
        if len(parts) < 4:
            continue
        name, path = parts[1], parts[2]
        if name in ("NAME", "---", "name") or not path or path.startswith("---"):
            continue
        paths.append((name, path))

dest_root = "GOLDEN_DOCS/docs"
# Remove docs no longer in the index, then re-copy everything current.
if os.path.isdir(dest_root):
    shutil.rmtree(dest_root)
copied = 0
for name, path in paths:
    dst = os.path.join(dest_root, path)
    os.makedirs(os.path.dirname(dst), exist_ok=True)
    shutil.copy2(path, dst)
    copied += 1
print("copied", copied)
PYEOF

cp EMILY/context/golden-docs-index.md GOLDEN_DOCS/context/
cp EMILY/context/full-system-context.md GOLDEN_DOCS/context/
cp EMILY/context/golden-docs-sprawl-memo-2026-06-12.md GOLDEN_DOCS/context/
cp EMILY/context/golden-repos.json GOLDEN_DOCS/context/
cp EMILY/context/mjolnir-context.md GOLDEN_DOCS/context/
cp CLAUDE.md GOLDEN_DOCS/context/MONOREPO_CLAUDE.md
cp EMILY/docs/ECOSYSTEM_CONTINUITY_REPORT.md GOLDEN_DOCS/context/
```

Then regenerate `MANIFEST.md` (sha256 + size per file — see this file's own generation script in
this repo's git history, commit `2d3a931`, for the exact one-liner), commit, and push.

## The standing instruction

The monorepo's own root `CLAUDE.md` carries a standing instruction (added 2026-09-21) telling
Claude Code to run this resync — as part of the SAME commit/session that changes a golden doc,
not as a separate later pass — whenever it adds, removes, or meaningfully edits a golden doc or
`golden-docs-index.md` itself. That's the actual mechanism keeping this repo current for now.
